Care Ladder Console UI/UX Guide

The single source of truth for the look and behavior of the Care Ladder facility console: the full SaaS shell with Alert center, Cases, Audit, People, Places, Staff, Channels, Billing and Settings. Follow it exactly and the implementation will match the approved mockup without drift.

How to use this guide

This document is written for the coding agent implementing or extending the console. It is prescriptive: token values, pixel dimensions, component anatomy and copy rules are specifications, not suggestions. Where a rule is enforceable in code review or CI it is marked with a CHECK tag.

  • Fixed — color tokens, type scale, spacing scale, component anatomy, state styles, copy terminology. Changing these requires a design decision, not a whim.
  • Flexible — minor paddings inside a component (±4px), copy that follows the terminology rules, ordering of secondary info.
  • Forbidden — everything in section 12 (Anti-patterns). These exist because each one appeared in a previous iteration and was rejected.

The approved mockup (mockups/console-full-saas.html) is the visual reference. When this guide and the mockup disagree on a detail, this guide wins; report the discrepancy rather than resolving it silently.

01

Design principles

Five principles explain every rule that follows. When you must improvise, improvise in their direction.

  1. Calm command center. The console is watched for hours and read in seconds. One accent color, dark surfaces, generous hierarchy. Urgency is communicated by a small set of semantic colors reserved for triage — never by decoration.
  2. Resident answers first. The response layer (positive closes, negative raises, silence escalates) is the product's core idea and must remain visually first-class: reply quotes, origin chips and the response-outcome violet are structural, not ornament.
  3. Honest states. Every surface shows what is actually happening: stubs say stub, missed windows say missed, empty lists explain what would populate them. Never render a control that does nothing.
  4. Numbers where numbers matter. Times, countdowns, medians and counts are always mono with tabular figures, always paired with their target ("24m 39s / 15m 00s") so health is judgeable at a glance.
  5. One system, ten views. Sidebar shell, topbar, card, chip, badge, table and register-row are shared vocabulary across all views. A new view is composed from these, not invented.
02

Color system

Dark theme, single accent, four semantic families. Copy this block verbatim as the console's :root CHECK — token names are part of the API. 

:root{
  /* surfaces */
  --bg:#0b0f14; --side:#0d1319; --card:#121820; --card2:#0e141b; --raise:#161f2a;
  --border:#1f2a36; --border2:#2b3a49;
  /* text */
  --text:#e8eef4; --muted:#8b9bab; --faint:#5f7189;
  /* accent — the ONLY brand color */
  --accent:#18a4c2; --accent-deep:#0e7490; --accent-ink:#04141a;
  --accent-soft:rgba(24,164,194,.12);
  /* semantic — reserved, see rules below */
  --ok:#34c98e; --warn:#f5b544; --bad:#f4574d;
  --p1:#f4574d; --p2:#f5a044; --p3:#5b8def;
  --vio:#b9a6ff; --vio-soft:rgba(185,166,255,.11);
  --radius:12px;
}

There is no shadow system. Elevation is border + surface step: a raised thing gets --border2, a recessed thing gets --card2. Never add box-shadow for depth CHECK.

2.3 The accent

Teal --accent #18a4c2 is the only brand color. It appears on: the active nav item, selected outlines, links, primary buttons (with --accent-ink text), the logo mark gradient (with --accent-deep), "key" timeline lines, and filter chips in their on state. If a new element feels like it needs accent, it probably needs hierarchy instead. Accent fills use --accent-soft behind --accent text.

2.4 Semantic colors — usage is policed

--bad and --p1 share a hex on purpose: at triage glance, red means "top of the ladder" wherever it appears. Do not introduce a second red.

2.5 Forbidden colors

  • No pure #000 or #fff anywhere CHECK.
  • No gradients except the logo mark and the (subtle) page-top scrim behind the sticky header.
  • No new hues. Purple exists only as the response-layer violet; indigo defaults are an anti-pattern (see §12).
  • State colors never recolor text that is not stating that state.
03

Typography

Two families only, both system stacks (offline-safe, no webfont fetches) CHECK:

--sans: -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
--mono: ui-monospace, "SF Mono", Menlo, Consolas, monospace;

3.1 Scale (type ramp)

RoleSize / lineWeightNotes
View title (topbar)16px / —700The only 700 in the UI
Card heading11px700UPPERCASE, letter-spacing .1em, color --faint
Card / section body14px / 1.5400Base body size
Row titles, names13.5px650Alert titles, register rooms, staff names
Small text12px400Meta sentences, notes
Chips10.5px400–600Pill borders, --muted text
Badges (UPPERCASE)9.5px750letter-spacing .05em
KPI value21–24px750tabular-nums; small unit suffix at 10.5px
Mono meta10–12px400–500timestamps, ids, durations, targets

3.2 Rules

  • Everything numeric is mono — durations, clocks, counts, thresholds, ids. Pair value + target: 0m 52s / 5m 00s.
  • UPPERCASE always gets letter-spacing: .05em badges, .1em card headings, .12–.14em kickers CHECK.
  • Sentences are sentence case. No all-caps sentences, no Title Case For Every Word in UI labels ("Acknowledge", not "Acknowledge The Case").
  • Max 8 type roles on a screen. If a new role seems needed, reuse one.
  • Line length for explanatory paragraphs: ≤ 62ch.

Layout & spacing

4.1 The shell

grid232px sidebar + minmax(0,1fr) main
sidebarsticky, full height, own scrollbar; background --side; collapses to a wrapping top row under 980px
content columnmax-width 1160px, centered, padding 20px 22px 44px
topbarsticky, rgba(11,15,20,.92) + backdrop-filter: blur(8px), height ~56px: view title + crumb, plan pill, clock, avatar

4.2 The two content patterns

  • grid2 — minmax(0,1fr) 330px: queue + detail panel (Alerts), cases + capacity (Cases), billing compare. The right column is always position:sticky; top:74px. Collapses to one column under 980px.
  • full-width card stack — tables (People, Places, deliveries), channel grid (auto-fit minmax(230px,1fr)), settings rows.

4.3 Spacing scale

Base unit 4px. Use 4 / 8 / 10 / 12 / 14 / 16 / 20 / 26 px steps. Card padding 14px 16px; card gap 14px; alert row gap 10px; intra-row element gap 8–10px. Section top margin inside a view: 16px. Between views: n/a (only one view renders).

4.4 Radii

--radius: 12px for cards and alert rows; 9–10px inner boxes and buttons; 999px pills (chips, plan pill); 3–6px tiny elements (badges, code). Never mix a new radius CHECK.

Component specs

5.1 Buttons

.btn--card bg, 1px --border, --text, radius 9px, padding 7px 13px, font 12.5px
.btn.primary--accent bg, --accent-ink text, weight 650 — one per view max
.btn.danger--bad bg, near-black text, weight 700 — "Escalate now" only
.btn.subtle11.5px, padding 5px 10px — inline actions inside cards
hoverborder-color → --accent (no bg change)

5.2 Chips and badges

  • Chip — informational metadata pill: 1px --border, --muted text, 10.5px. Variants: .hot (bad border/text) for negative/missed, .ok for can-de-escalate.
  • Badge — status stamp: soft bg + colored text, UPPERCASE 9.5px/750. Map: ok→b-ok, handling/warn→b-warn, missed/needs-owner→b-bad, resolved-by-response→b-vio, informational→b-info (accent).
  • Priority chip — .pri: mono-weight P1/P2/P3 on --card2 with border; text colored by family.

5.3 Alert card (Alert center queue)

┌─ card: --card, 1px --border, LEFT border 4px colored by priority, radius 12
├─ row1: [pri chip] [title: place · person, 650] [chips…] …[mono meta right]
├─ row2 (chips): state chips — "negative reply" .hot, "aging 14m", "02:41 to target"
└─ .reply (when a resident reply exists): --card2 bg, 3px LEFT border --bad,
   italic quote 12.5px + mono classification line 10px --faint
  • Selected card: outline: 2px solid --accent; outline-offset: 2px plus role="button" tabindex="0" aria-selected CHECK (keyboard: Enter/Space opens).
  • Aging chip switches to .hot when the ack target passes ("ack window missed"), never clamps at "0m".

5.4 Detail panel (right column)

Stack of .dsec sections separated by hairlines: heading (UPPERCASE 10px) + content. Fixed order: identity → resident response → ladder → reprioritize → assign → override. Form state (assign select, pull-off-break checkbox) must survive 20s refreshes CHECK.

5.5 Ladder (mini rung list)

row18px rail col + name + right mono timestamp
dot statesdone = filled accent · current = warn ring pulse · stop = filled ok · jump = filled bad · future = border only
names12px 600; done rows drop to --muted

             keyboard: role=button tabindex=0; aria-expanded

5.7 Staff row

Avatar circle (26px, --raise, initials 10px) + name/role + right status badge + inline break actions. Statuses: available ok · on_case accent-soft · on_break violet with countdown text ("on break · 18m left") · dimmed row at 55% opacity when not assignable CHECK.

5.8 KPI box

--card, 1px border, radius 12, padding 12–14px. Value 21–24px/750 mono + 10px UPPERCASE label in --faint. Value color only from: default text, ok, warn, bad, vio. Grid: 4 per row (6 on Audit), 2 under 980px.

5.9 Banner

Full-width, radius 12, 1px border + soft tinted bg: good (ok) for "floor self-managing", info (accent) for the response-model explainer. Icon 16px inline SVG + bold clause + --muted sub-line. One banner per view max.

5.10 Toast

Fixed bottom-right, --card bg + border (bad border when error), radius 10, auto-hide 4s, role="status" aria-live="polite" CHECK. The only global overlay.

5.11 Table (People, Places, deliveries)

.tbl: 12.5px, header UPPERCASE mono 9.5px --faint, row hairlines, hover --card2. Status cells use badges; id/time cells use mono. No zebra striping, no vertical rules.

06

States

Every interactive element ships with the full cycle; missing states are bugs CHECK.

StateRule
HoverBorder → accent (buttons, rows, chips). Nav items get --raise fill. No scale/translate transforms.
Focus-visibleoutline: 2px solid --accent; offset 2px on every focusable: buttons, selects, alert cards, register heads, tabs CHECK. Never remove outlines.
SelectedAlert card outline + aria-selected; nav item accent-soft fill; register row stays open until another opens (accordion).
LoadingContainer opacity .45 + pointer-events:none during refresh. No spinners.
EmptyNamed empty states that say what populates them: "Floor clear. No open alerts." / "No closed cases or resident resolutions today." Never blank.
ErrorAction failures surface inline (form-error under the field) + toast. API 401 redirects to sign-in.
DisabledOpacity .45–.55 + cursor:default; break-option rows for on-break staff render dimmed, not hidden.
Missed windowAck countdown flips to .hot "ack window missed" — a first-class state, not a clamped zero.
07

Motion

  • The console is nearly static by design. Allowed motion: toast fade, current-rung pulse (1.8s ease-in-out box-shadow ring), caret rotate 90° on register open, break countdown text ticks.
  • All animation lives behind @media (prefers-reduced-motion: no-preference) CHECK.
  • Forbidden: scroll-triggered reveals, hover bounce/transitions on transform, page-enter animations, any parallax.
  • Poll cadence: roster/queue re-render every 30s; full refresh after actions. Preserve scroll position and form drafts across re-renders.
08

Iconography

  • All icons are inline SVG, single-line stroke style, stroke-width 2–2.4, 16–20px, currentColor CHECK. No icon fonts, no icon CDN, no emoji as UI icons.
  • The product mark is the ladder glyph: two rails + three rungs, drawn with round linecaps. It is the only place the accent gradient is allowed. Banner/alert icons are simple outline shapes (bell, check-shield, warning triangle).
  • Channels use single-letter tiles on brand-dark backgrounds (Slack aubergine #4a154b, Teams blue #5072c4, WhatsApp green #1e3a2f, Telegram slate) — letter + color reads faster than logos and avoids brand-asset copying.
  • One icon per meaning; do not decorate text with repeated icons.

11

Accessibility floor

  • Text contrast: body ≥ 4.5:1 (verified: --text 13.9, --muted 6.1 on card); --faint reserved for ≥12px mono metadata CHECK.
  • Keyboard: tabs, alert cards, register heads, all buttons focusable; Enter/Space activates; visible focus ring everywhere CHECK.
  • ARIA: tabs use role=tablist/tab/tabpanel + aria-selected; banners role=status; toasts aria-live=polite; accordions aria-expanded; priority segments are role=group with labels.
  • Color never carries meaning alone — every colored chip/badge includes its word (P1, missed, break) CHECK.
  • Touch targets ≥ 36px on interactive rows/buttons at mobile widths.
12

Anti-patterns (each one shipped and was rejected)

doLeft 4px priority border on a 12px-radius card, flat surfaces, hairline separations.
dontRounded card + colored left border at larger radii + drop shadow — the generic AI dashboard block.
  • Light/dark split — one dark system for the whole product. The old home console's light theme is retired, not extended.
  • Multiple accents — no second brand hue, no per-view recoloring, no indigo #6366f1-family defaults.
  • Emoji as icons — replaced once already; do not reintroduce.
  • Stub controls — no button that toasts "coming soon". Hide unwired features.
  • n/a walls — never render timing rails/tables of nulls; hide the block.
  • Clamped countdowns — "0m to target" forever is a bug; missed is a state.
  • Raw ids as identity — owners render names + initials; enums render labels ("negative reply", not "from_negative_reply").
  • Demo chrome above product — demo strip collapses by default on deployed instances.
  • Monospace body text — mono is for numbers/ids only.
  • New reds/oranges — semantic hues are closed set (§2.4).
13

Implementation notes

  • Files: the console lives at src/care_ladder/api/static/facility/index.html (self-contained, no build step). The shell adds views as <section class="view" id="view-X"> + sidebar data-view entries; the tiny router in the mockup's script is the pattern.
  • Tokens first: paste the §2 block as-is; components reference tokens, never hex literals CHECK.
  • Test hooks: existing tests grep served bytes — keep these strings intact: Alert center, Cases, Audit, pull_off_break, /facility/staff, /facility/alerts, /facility/audit/summary, data-fixture="facility_negative_reply", Path A (home console), and no \u2014 em dash anywhere CHECK.
  • Data contract: render from the existing endpoints; new views (People/Places/Channels/Billing) read new read-only endpoints — keep payloads shaped for the components (rows with badges + mono fields), and hide any metric the backend cannot fill honestly (see §12 n/a walls).
  • Timestamps: the drill-down depends on event at stamps; until the backend records them, the Timing rail stays hidden rather than rendering nulls.
  • Mobile: one breakpoint at 980px (sidebar → top row, grid2 → single column, KPI → 2-up, register hides owner/handling columns).
14

Pre-merge checklist

  • Token block matches §2 verbatim; no hex literals outside :root.
  • One primary button per view; danger only on escalate.
  • Focus-visible rings on every interactive element; keyboard pass completes: tab through Alert center → select card → assign → switch tabs → open a register row.
  • Every colored status carries its word; every number is mono with its target.
  • No em dash, no emoji icons, no stub toasts, no n/a rails, no clamped countdowns.
  • Empty states present for: queue, cases, register, roster, deliveries.
  • Reduced-motion respected; no new animation types.
  • Test-grep strings (§13) intact; full suite green.
  • Screenshot diff against console-full-saas.html at 1480px and 390px — layout skeletons must match; report intentional deviations.
